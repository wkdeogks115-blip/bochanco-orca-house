# 변경 절차

기본 순서:
`VERSION_CHECK → READ_ONLY_INSPECTION → PLAN_ONLY → CANDIDATE → STATIC_REVIEW → RISK_CLASSIFY → APPLY/APPROVAL → AFTER_CHECK → REPORT`

## Low-risk
격리 Candidate, read-only 검사, 로컬 simulation, reversible test는 범위가 명확하면 진행 가능하다.

## High-risk
삭제/데이터손실, 설치/업데이트, 시스템 경로/Registry/Service, 관리자 권한, 외부 전송, deploy, merge, 결제, credential/secret 취급은 명시적 범위 승인 없이 하지 않는다.

## GitHub
- `main` 직접 수정 금지 원칙.
- Candidate branch + Draft PR 선호.
- merge/deploy는 별도 Gate.
